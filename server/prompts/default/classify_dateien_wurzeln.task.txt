[AUFGABE]
Analysiere den Benutzer-Prompt und bestimme:
1. action: {aktionen_text}
2. pfad: NUR bei create — der Pfad, so wie der Mensch ihn genannt hat, unveraendert
3. bezeichnung: wie der Mensch das Verzeichnis nennt ("meine Projektdoku") — bei create optional, bei update Pflicht
4. stichwort: bei update/delete/reactivate ohne Nummer — das Wort, mit dem der Mensch die Freigabe anspricht
5. target_id: bei update/delete/reactivate — die Nummer der Freigabe, falls er sie nennt
6. normalisiert: der Auftrag in Fachsprache (siehe [FACHSPRACHE])
7. grund: NUR bei rejected — kurze Begruendung (1 Satz)

VORPRUEFUNG — geht es ueberhaupt um ein Verzeichnis als Ganzes?
Entscheidend ist der Bezug auf ein VERZEICHNIS, nicht auf eine Datei darin und
nicht auf einen Inhalt.
Wenn kein solcher Auftrag erkennbar ist → action: "rejected"
Im Zweifel: rejected.

Beispiele fuer rejected:
- "Was steht in der Roadmap?" → das ist eine Frage nach Inhalt
- "Such mal nach dem Abschnitt ueber Salienz" → das ist eine Suche, keine Freigabe
- "Das liegt bei mir unter Projekte" → eine Erwaehnung ohne Freigabeabsicht
- "Leg mir das bitte ab" → hier wird geschrieben; dieser Dienst schreibt nichts

Beispiele fuer ECHTE Auftraege:
- "Du darfst in /dokumente nachsehen" → create
- "Nimm das Verzeichnis wieder weg" → delete
- "Worauf hast du Zugriff?" → read
- "Nenn das ab jetzt meine Projektdoku" → update
- "Gib die Projektdoku wieder frei" → reactivate

Aktionen-Beschreibung:
- create: Ein Verzeichnis freigeben
- read: Die bestehenden Freigaben auflisten
- update: Die Bezeichnung einer Freigabe aendern — NIE ihren Pfad
- delete: Eine Freigabe zurueckziehen
- reactivate: Eine zurueckgezogene Freigabe wieder aufnehmen
